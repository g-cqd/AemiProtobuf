## What came in, in order

- **0008.** The comparator matches `buf breaking` (WIRE rules) on fourteen kinds of change. A linter matches `buf lint`'s BASIC
  naming rules. Both are available as the `aemi-proto-check` tool and the `swift package protobuf-check` plugin.
- **0006.** `DynamicMessage` and `DynamicSchema` read and write any message type a descriptor set declares, iteratively,
  with field semantics resolved once from the edition features. 32 protoc-encoded cases round-trip byte for byte.
  `ProtoMessageView` reads a message in place; the probe found it 1.5× faster than a full decode for half the fields, but only
  after its index array was reserved up front. Before that it lost to the macro decoder, whose short strings sit inline in
  `String`.
- **0010.** `AemiProtobufJSON`, the proto3 JSON mapping over dynamic messages, on AemiJSON's parser. The conformance testee
  answers JSON through an embedded descriptor set. Two lessons from the suite: an `Any` of `Empty` is `{"@type": …}` alone,
  because C++ does not count Empty as a well-known type; and extensions became ordinary fields of the message they extend,
  which fixed binary and JSON at once.
- **0002.** `ProtoCompiler` compiles `.proto` files exactly as protoc does: 20 roots, imports included, byte for byte.
  Options are interpreted as dynamic messages against an embedded `descriptor.proto`. Defaults use C's `%g`, computed from
  the exact decimal expansion. `retention = RETENTION_SOURCE` options are dropped, and an rpc with a `{}` body gets empty
  options; both were learned from protoc's output, not its documentation. `ProtoPrinter` writes source that compiles back to
  the same descriptors. The old subset parser is gone; `ProtoParser` fronts the new one.
- **0011.** `ProtoTextFormat`, plus a seeded differential: 120 random messages, protoc as the oracle. protoc keeps duplicate
  map keys on both its text path and its `--decode` path, so for maps it cannot be the oracle of "the last key wins". The
  corpora state that case instead.
- **0005.** The macros write each type's definition (`AemiProtoDefined`, in edition 2023). `ProtoDefinitions.file(for:)`
  gathers the definitions; the compiled descriptor reads what the macro writes.
- **0014.** `AemiProtobufNIO`: `ByteBuffer` read in place, frames read a piece at a time, channel handlers.

## Speed

Measured on the 1,000-user corpus, release p50. Each step is recorded in the research notes and the roadmap entries.

| Path | First version | Now |
|---|---|---|
| Dynamic decode | 6.37 ms, 41 K mallocs | 3.06 ms, 17 K |
| Dynamic encode | 3.46 ms | 2.04 ms |
| JSON encode | 14 ms, 61 K mallocs | 4.4 ms, 27 mallocs |
| JSON decode | 9.3 ms, 49 K mallocs | 6.1 ms, 18 K |
| View, half the fields | 924 µs | 507 µs (macro decode: 771 µs) |

The causes were bookkeeping, not data:
- an `indirect enum` boxing every scalar;
- descriptor structs copied on every field read;
- paths built for errors that never happen;
- an index array growing five times per message.

Compiling `descriptor.proto` takes 1.1 ms. The tiny `parse3Fields` went from 7 to 21 mallocs, because a full tokenizer
replaced the subset parser, and `compileDescriptorProto` gained 95 mallocs in the last refactors. Both thresholds were raised,
on purpose.
