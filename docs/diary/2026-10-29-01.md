# 2026-10-29 — CI on 6.4, and a conformance review before analyzerkit relies on the macro

## CI

The first two runs had failed before compiling: the runner's Swift 6.3.3 refused tools version 6.4.0, and swift-format was not on
PATH. Every job now installs the `.swift-version` toolchain; `quality.sh` finds swift-format in three places. Green on the first run
with the fix (`a53a089`, run 40959879484). Linux still never runs (now roadmap 0029).

## The review

analyzerkit is about to put every tool's cache payloads on `@ProtoMessage` (its roadmap 0017). Before that, a probe of the
specification's decode rules against the macro (research 2026-10-29-conformance-review). Most hold. Four do not: a message field given
twice replaces instead of merging, unknown fields are dropped, an unknown open-enumeration value is lost, and an empty non-optional
nested message is written. None of them is something our own caches hit (each entry is written once, by the same type), which is why
nothing noticed; all of them are things any other producer can send.

The official conformance runner needs much more than these fixes: maps, `oneof`, messages that hold themselves, proto2. So the order
is the four fixes (0020–0023), what the conformance messages need (0024–0027), a generator from descriptor sets so those 400 fields
are not hand-written (0028), then the runner (0011). The harness (0012) comes before the speed items so they, and the decode cost the
fixes add, are measured on one footing.
