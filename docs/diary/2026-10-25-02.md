## What mutation testing and the benchmarks found

Experimental tier: 99 mutants (95 viable, 4 did not compile). First run: **88 killed, 7 survived (92.6%).** Reading the 7:

- `WireWriter.appendBytes`: `bytes.append(contentsOf: value)` removed — survived because the only test passed `[]`. Added a
  non-empty test.
- `WireReader.run` and `WireWriter.appendMessage`: `<=` to `<` on `maxMessageBytes` — no test sat on the boundary. Added both.
- `FieldTag.init`: `rawValue <= UInt64(UInt32.max)` mutated to `<` — added `0xFFFF_FFFF` (valid 32-bit, wire type 7).
- `FieldNumber.<`: `<` to `<=` — never called. Added an ordering test.
- `WireWriter.init`: `bytes.reserveCapacity(capacity)` removed — observable only by allocation count, which the benchmark threshold
  gates. Remains in the mutation baseline as an equivalent mutant for functional tests.

Benchmarks (release, p50, this machine): `Users1000.write` 297 µs, **1 malloc**; `Users1000.read` 380 µs, 1,000 mallocs;
`Varint4096.write` 23 µs, 1 malloc; `Varint4096.read` 21 µs, **0 mallocs**; `Group3Deep1000.skip` 125 µs, **1,010 mallocs**. The
1,010 allocations in `skipField` are one `[FieldNumber]` per group; queued as roadmap 0016. A trap found along the way: Benchmark
splits a benchmark's name on `:` when it reads thresholds, so names with colons never matched their own files. Renamed to `Users1000.write`.
