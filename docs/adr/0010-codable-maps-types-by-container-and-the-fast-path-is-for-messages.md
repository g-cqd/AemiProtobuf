# 0010 — Codable maps Swift types by container; the fast path is for messages

## Context

ADR-0009 gave `Int`, `String`, `Array` and the other scalars `AemiProtoFast*` conformances, and described a pooled encode
buffer. Probing the result (roadmap 0004 reassessment, `Benchmarks/Comparison`) showed three faults:

1. A bare scalar is not a protobuf message. `encode(5)` wrote the byte `05`; `encode(["a", "b"])` wrote a message of field 1
   holding nested strings. Neither is valid for any `.proto`.
2. `Array<Element>` conformed whenever `Element` did, so a `[String]` field inside a message matched the fast path in the
   keyed container and was written as a nested message of field 1.
3. The Codable containers were a prototype: arrays of messages and nested containers trapped or were dropped, an absent
   optional could not be told from a set zero, nesting limits reset at each level, and `try?` hid malformed input. The
   generic path failed to round-trip an ordinary list of nested records.
4. `EncoderBufferPool` was never called by `ProtobufEncoder`.

## Decision

- **Fast path:** only a message type conforms (hand-written now, generated by `@ProtoMessage` later). The scalar
  conformances and `EncoderBufferPool` are removed. `Array` stays, as a top-level list written as repeated field 1, and the
  keyed container never takes the fast path for a sequence.
- **Codable maps by container.** Scalars map by Swift type (table on `ProtobufEncoder`). A keyed container is a message; an
  unkeyed container is a repeated field (numbers packed, strings, bytes and messages one record each); a single-value
  container is a scalar, which is how a raw-value enum becomes a varint.
- **Presence.** `encode` omits a default value (proto3). `encodeIfPresent` writes a set value, zero included. A non-optional
  nested message is always written.
- **One index per message on decode** (`_ProtobufMessageIndex`): field occurrences in wire order, payloads by range, never
  copied. A singular field takes its last occurrence, a repeated nested message given twice merges, packed and unpacked
  numbers mix. A wire type that does not match the requested Swift type throws.
- **Limits hold at every level.** The writer's `beginMessage`/`endMessage` and the reader's `withReader(over:in:depth:)` carry
  the depth, so Codable nesting obeys `WireLimits` exactly as the core does.
- **Unsupported constructs throw** `ProtobufEncodingError.unsupported` or `ProtobufDecodingError.unsupported`: dictionaries,
  nested containers made by hand, `superEncoder`, a top-level scalar or array. None traps.
- **Oracle.** `Resources/outer.bin` is `protoc --encode` output for a message that uses each construct; the encoder must
  write exactly those bytes and the decoder must read them back.

## Consequences

- `sint*`, `fixed*`, `sfixed*`, `map` and `oneof` still need a descriptor or the fast path (open: roadmap 0005, 0006).
- A message with duplicate field occurrences costs an index entry per occurrence: at most 12 times the message size, inside
  `WireLimits.maxMessageBytes`.
